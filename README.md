# 本地费用报销台

记录费用、整理报销材料并管理审批状态。面向本地单机使用，采用 Python 3 标准库与 SQLite，无需安装第三方依赖。

## 使用

入口为 `python -m expense_desk`，`--db` 必填，指定 SQLite 数据库文件；相对路径按当前工作目录解释，父目录存在时自动创建新库。

提交报销单：

```sh
python -m expense_desk --db demo.sqlite submit \
  --submitter 演示甲 --purpose 演示交通 --amount 12.30
```

成功时向标准输出输出一条 JSON 记录（退出码 0）：

```json
{"id": 1, "submitter": "演示甲", "purpose": "演示交通", "amount_minor": 1230, "status": "pending"}
```

提交时可选用 `--attachment-note` 为凭据附带一段文字说明，内容只作为普通文本随单保存，不读取文件或访问网络；提供时去除首尾空白，内部空格、中文、逗号、双引号与换行原样保留。提供说明的记录（含提交成功输出与 list 结果）在原有五个字段之后增加 `attachment_note` 字符串字段；未提供该参数的记录仍只有五个字段，不输出空串或 null：

```sh
python -m expense_desk --db demo.sqlite submit \
  --submitter 演示甲 --purpose 交通 --amount 12.30 --attachment-note "  演示车票  "
```

```json
{"id": 1, "submitter": "演示甲", "purpose": "交通", "amount_minor": 1230, "status": "pending", "attachment_note": "演示车票"}
```

按提交人查询（完整名称精确匹配，按 id 升序）：

```sh
python -m expense_desk --db demo.sqlite list --submitter 演示甲
```

list 可另加可选的 `--status`：去除首尾空白后仅接受区分大小写的 `pending` 与 `approved`，记录须同时满足提交人与状态才进入结果；省略时查询范围、返回内容与排序不变。空串、纯空白、大小写不同或其他取值退出码 2 并提示“状态无效”，缺少参数值退出码 2 并指出 `--status`；提交人校验先于状态校验，两者都在数据库操作前完成。筛选只作用于本次查询，不保存选择，也不新增或修改记录。

按编号批准单张报销单，把该单状态由 `pending` 改为 `approved`：

```sh
python -m expense_desk --db demo.sqlite approve --id 1
```

成功时向标准输出输出一条与 list 单条记录字段一致的 JSON（退出码 0，标准错误为空），仅 `status` 变为 `approved`：

```json
{"id": 1, "submitter": "演示甲", "purpose": "交通", "amount_minor": 1230, "status": "approved", "attachment_note": "演示车票"}
```

批准结果写入 SQLite，之后的新进程（list / export 等）读到的都是 `approved`。重复批准已是 `approved` 的记录为幂等操作：仍退出 0 并返回同一条记录，不改变任何内容（前导零等价，如 `--id 001` 与 `--id 1` 相同）。编号不存在（含父目录存在的全新数据库）退出码 2 并提示“报销单不存在”，不新增记录；记录状态既不是 `pending` 也不是 `approved` 时退出码 2 并提示“当前状态不能批准”。

`--id` 为必填参数：去除首尾空白后只接受 ASCII 数字组成、数值在 1 至 9223372036854775807 之间的整数，允许前导零。空串、零、负数、小数、带正号、非 ASCII 数字（如全角数字）与越界值一律退出码 2 且标准错误包含“编号无效”；缺少 `--db`、`--id` 或其参数值退出码 2 并指出缺少的参数。编号校验先于数据库操作：编号与数据库路径同时无效时优先报告编号错误，不创建数据库文件。

按提交人汇总笔数与合计（整数分），并可选 `--budget` 提供一次性预算参考（人民币元，格式与金额相同）、可选 `--status` 仅统计指定状态的记录：

```sh
python -m expense_desk --db demo.sqlite summary --submitter 演示甲 --status approved --budget 15
```

提供 `--status` 时去除首尾空白后仅接受区分大小写的 `pending` 与 `approved`，仅统计同时匹配提交人与状态的记录；省略时统计范围与输出维持原样，不增加状态字段。空串、纯空白、大小写不同（如 `Pending`）或其他取值退出码 2 并提示“状态无效”，缺少参数值退出码 2 并指出 `--status`。业务校验按提交人、预算、状态的顺序进行，全部通过后才访问数据库；预算与状态同时无效时报告预算错误，其余参数有效而状态与数据库路径同时无效时报告状态错误，均不创建数据库文件。

提供预算时，在原有 `submitter`、`count`、`total_amount_minor` 之外增加 `budget_amount_minor`（预算整数分）与 `remaining_amount_minor`（预算减本次筛选后合计的整数差额，正为尚有剩余、零为用完、负为超额；未命中任何记录时笔数与合计均为整数零，余额等于预算）；不带 `--budget` 时只输出原有三个字段。状态筛选与预算都只作用于当次汇总，不写入数据库，也不新增或修改费用记录。

## 规则

- 币种固定为人民币；金额以整数分存储（`12`、`12.3`、`12.30` 分别为 1200、1230、1230 分），字符串换算，不经过浮点。
- 金额只接受 ASCII 数字整数，或整数部分加小数点及一至两位小数，且数值大于零、换算后不超过 64 位有符号整数上限。零、负数、科学计数法、超过两位小数（含 `12.300`）等格式一律拒绝。
- 提交人与用途去除首尾空白后不能为空；查询对提交人做同样处理并精确匹配。
- 每条记录保存稳定正整数 id、提交人、用途、整数分金额与状态（提交后为 `pending`，经 `approve` 批准后为 `approved`）；提供 `--attachment-note` 时再保存附件文字说明。相同内容重复提交生成独立记录，数据在重启后保留。
- 批准按编号作用于单张报销单：`pending` 改为 `approved` 并落盘；已是 `approved` 时幂等返回同一记录、退出 0、不改变记录。编号、提交人、用途、整数分金额与附件文本均原样保留，无说明的记录仍不输出 `attachment_note`；旧五列数据库与带附件说明的数据库都可批准。批准不影响 `list` 的提交人精确匹配与 id 升序；省略 `--status` 时 `summary` 仍统计该提交人的全部记录（提供 `--status` 时仅统计匹配该状态的记录），`export` 仍为固定五列 CSV 并输出每条记录的实际状态。
- 附件说明为可选普通文本：只去除首尾空白，内部空格、中文、逗号、双引号与换行原样保留，不读取文件、不访问网络。显式传入空串或仅含空白的说明退出码为 2（标准错误为“附件说明不能为空”），不新增记录、不创建数据库文件；缺少参数值退出码同样为 2 并指出缺少参数值。说明校验排在提交人、用途与金额校验之后、数据库操作之前，其他字段有效而说明与数据库路径同时无效时优先报告说明错误。
- 已有数据库可直接使用：旧记录仍返回原来的五字段内容（无空串或 null 占位），可与带说明的新记录一起查询，旧记录的 id、金额、用途与状态不变；`summary` 与 `export` 不包含附件说明，CSV 仍为固定五列。
- 缺少必需参数、空提交人、空用途、无效金额、无效 `--budget`、list/summary 的无效 `--status`、无效或不存在的批准编号、不可批准的状态退出码为 2；数据库无法创建、打开、读取或写入时退出码为 1。两种失败均不向标准输出输出内容，原因写入标准错误，且失败操作不会新增或改变记录。summary 同时给出无效预算与无效数据库路径时，优先报预算错误（退出码 2）且不创建数据库文件；summary 同时给出无效状态与无效数据库路径（其余参数有效）时，同样优先报状态错误（退出码 2）且不创建数据库文件；approve 同时给出无效编号与无效数据库路径时，同样优先报编号错误（退出码 2）且不创建数据库文件。
